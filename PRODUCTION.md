# HealthLink Maroc — Production Operations

National-scale healthcare platform for Morocco. Stack: TanStack Start + React + Tailwind + Lovable Cloud (Supabase).

## 1. Environments

| Env | URL | Backend |
| --- | --- | --- |
| Development | preview iframes | Lovable Cloud (Test) |
| Staging | preview deploy | Lovable Cloud (Test) |
| Production | https://health-maroc-connect.lovable.app | Lovable Cloud (Live) |

Each environment has isolated secrets, feature-flag rollouts and audit logs.

## 2. CI/CD

Lovable manages build + deploy on every commit. Frontend changes go live when **Update** is clicked in the publish dialog. Backend changes (migrations, edge functions, cron) deploy immediately on apply. Rollback = revert the commit and re-publish.

Recommended GitHub Actions baseline (for downstream forks):

```yaml
name: CI
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v1
      - run: bun install
      - run: bunx tsgo --noEmit
      - run: bunx vitest run
      - run: bun run build
```

## 3. Scalability

- Postgres connection pooling enabled. For >50k concurrent users upgrade via **Cloud → Advanced → Upgrade instance**.
- Every hot query has an index; verify with `supabase--slow_queries`.
- Partitioning candidates: `api_metrics`, `analytics_events`, `notifications` (by month) once each exceeds ~50M rows.
- CDN: Cloudflare in front of every static asset, managed by Lovable.
- Client cache: TanStack Query with route-level `ensureQueryData` + suspense.
- Background work: `pg_cron` (appointment reminders, trust recompute, daily aggregates).
- Push: web-push via `notifications` table and dedicated messaging worker.

## 5. Backup & DR

- Daily automated PG backups + 7-day PITR (Lovable Cloud default).
- Manual export: **Cloud → Database → Tables → Download CSV**.
- Backup runs surfaced in `/admin/backups`.
- DR target: **RPO 24h, RTO 4h**. Restore drill quarterly.

## 6. Security (production)

- HTTPS enforced at the Cloudflare edge.
- RLS on every public-schema table; verified by `supabase--linter`.
- Rate limiting via `check_brute_force` and `check_notification_rate_limit` SQL functions.
- Secrets via Cloud secret manager (never committed).
- DDoS / WAF: Cloudflare managed.
- Trust scores + verification levels computed by `compute_provider_trust`.

## 11. Runbooks

- **Database down** → `supabase--cloud_status`; restart if `ACTIVE_UNHEALTHY`, resume if `INACTIVE`.
- **Spike in errors** → `/admin/monitoring`, sort by occurrences, resolve after fix.
- **Slow API** → `supabase--slow_queries` → `EXPLAIN ANALYZE` → add targeted index via migration.
- **PWA stuck after deploy** → ship kill-switch SW per PWA skill cleanup path.
- **Feature regression** → flip the feature flag at `/admin/flags` (rollback in seconds, no deploy).
